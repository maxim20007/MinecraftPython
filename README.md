# Minecraft-подобная игра на Python (3D) — стартовая болванка

Этот репозиторий — план и спецификация для **первой рабочей версии** Minecraft-подобной игры на Python в 3D.

Цель первой итерации:
- процедурно генерируемый (random) блочный мир;
- блоки без текстур (чистые цвета);
- типы блоков:
  - **трава** — зелёная (верхний слой);
  - **камень** — серый (под землёй);
  - **бедрок** — чёрный (самый нижний слой, ограничение мира);
- игрок (персонаж) может ходить;
- голубое небо.

---

## 1) Концепт MVP (минимально жизнеспособная версия)

### Что обязательно в MVP
1. Окно 3D-сцены и камера от первого лица.
2. Генерация чанка(ов) мира по высотной карте.
3. Рендер кубов трёх типов с цветами вместо текстур.
4. Коллизии игрока с блоками.
5. Передвижение: `WASD`, прыжок `Space`, гравитация.
6. Небо: однотонный голубой фон.

### Что можно отложить
- ломание/установка блоков;
- инвентарь;
- мобы;
- сохранение мира в файл;
- мультиплеер.

## 2) Рекомендуемый стек

Для максимально быстрого старта:
- **Python 3.11+**
- **Ursina Engine** (простой вход в 3D, подходит для прототипа voxel-игры)

Альтернатива:
- Panda3D (ниже уровень абстракции, сложнее старт);
- Godot + Python bindings (возможно, но для чистого Python обычно медленнее старт разработки).

## 4) Правила генерации мира (первая версия)

### Координаты
- Мир разбиваем на чанки, например `16x16` по XZ.
- Высота мира фиксированная, например `y = 0..31`.

### Слои
- `y = 0` → **бедрок** (чёрный).
- `1..(h-1)` → **камень** (серый).
- `y = h` → **трава** (зелёный верхний блок).

Где `h` — высота поверхности в данной точке `(x, z)`.

### Как получить random-рельеф
Самый простой старт:
- `h = base_height + random.randint(-2, 2)`

Более гладкий вариант (следующий шаг):
- Perlin/Simplex noise (`noise` библиотека).

## 5) Игрок и физика

### Персонаж
- Капсула/бокс-коллайдер.
- Скорость ходьбы (например, 5 м/с).
- Прыжок (вертикальный импульс).
- Гравитация (постоянное ускорение вниз).

### Камера
- От первого лица.
- Мышь управляет взглядом (`yaw/pitch`).

### Базовые коллизии
- Игрок не проходит сквозь блоки.
- При падении на землю скорость по Y сбрасывается.

## 7) План производства по этапам

### Этап 1 — Вертикальный срез (1–2 дня)
- Поднять окно и камеру.
- Отрисовать один тестовый чанк.
- Сделать управление игроком с коллизиями.
- Проверить, что есть небо и три типа блоков по слоям.

### Этап 2 — Улучшение генерации (1 день)
- Добавить noise вместо чистого `random`.
- Сделать несколько чанков вокруг игрока.

### Этап 3 — Оптимизация (1–2 дня)
- Простейший culling невидимых граней.
- Пул/кэш чанков.

### Этап 4 — Геймплейный минимум (по желанию)
- Удаление и установка блоков.
- Простейший хотбар.

## 8) Критерии готовности первой версии

Считаем болванку готовой, если:
1. Игра запускается одной командой.
2. Генерируется случайный блочный рельеф.
3. Верх — зелёная трава, под ней серый камень, низ ограничен чёрным бедроком.
4. Игрок может ходить/прыгать и сталкивается с миром.
5. Фон сцены — голубой.

## 9) Пример быстрого старта

### macOS / Linux (bash, zsh)
```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python src/main.py
```

### Windows PowerShell
```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python src/main.py
```

### Windows CMD
```bat
python -m venv .venv
.venv\Scripts\activate.bat
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python src/main.py
```

> Важно: в PowerShell не используется команда `source` (это команда для Unix-shell).
> Если `pip` не найден, используйте `python -m pip` — это надёжнее и кроссплатформенно.

## 10) Частые проблемы при запуске (Windows)

1. **`source` не распознано**
   - Причина: команда `source` работает в bash/zsh, но не в PowerShell.
   - Решение (PowerShell):
     ```powershell
     .\.venv\Scripts\Activate.ps1
     ```

2. **`pip` не распознано**
   - Причина: `pip.exe` может не быть в PATH текущей сессии.
   - Решение:
     ```powershell
     python -m pip install -r requirements.txt
     ```

3. **`ModuleNotFoundError: No module named 'ursina'`**
   - Причина: зависимости не установлены в активированное окружение.
   - Решение:
     ```powershell
     .\.venv\Scripts\Activate.ps1
     python -m pip install -r requirements.txt
     python src/main.py
     ```

4. **Белый/пустой экран после запуска**
   - Проверьте, что окно активно (кликните по нему мышью).
   - Подвигайте мышь и нажмите `W/A/S/D`: в этой версии камера стартует немного сверху, и можно смотреть почти в небо.
   - Если запуск долгий/чёрный экран в начале: это генерация первого мира; для MVP оставлен 1 чанк, чтобы ускорить старт.
   - Убедитесь, что установлен актуальный `ursina` из `requirements.txt`:
     ```powershell
     python -m pip install -U -r requirements.txt
     ```
   - Рекомендуемая версия Python: `3.11` или `3.12` (в `3.13` возможны нестабильности некоторых библиотек).
   - Если экран по-прежнему белый после обновления: удалите окружение `.venv`, создайте заново и переустановите зависимости.

## 11) Риски и решения

1. **Много кубов = просадка FPS**
   - Решение: чанки + объединение мешей + culling.
2. **Дёрганое движение камеры/игрока**
   - Решение: фиксированная обработка физики и ограничение `pitch`.
3. **Сложно масштабировать код**
   - Решение: сразу разделить на модули `world`, `player`, `settings`.
